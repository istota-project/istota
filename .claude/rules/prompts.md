# Prompt assembly: the two halves and the control directory

The layer order lives in `AGENTS.md`; the split by authority and its handoff live here. `executor.md` owns the rest of `execute_task()`.

## A task prompt is two halves

**A task prompt is two halves, split by authority** (`executor.ComposedPrompt`, ISSUE-375). `build_prompt` returns `system` and `user`, and the question a layer is sorted on is whether it has to stay verbatim for the life of the task, not how often it changes. Standing instructions — identity, execution constraints, emissaries, persona, workspace layout, tool descriptions, rules, response guidelines, skills changelog, eager skill bodies — are the `system` half. Retrieved memory, knowledge facts, playbooks, conversation and confirmation history, the request and its attachments are the `user` half, which is what a compaction summary carries forward instead. Everything used to travel as one string in the model's first *user* turn, so `NativeBrain`'s first compaction replaced Istota's identity, rules and tool surface with a model-written summary and the task ran on without them. Two rules follow from the split and are held by tests: no line in the system half may point at material in the user half (which is why the four time lines and the workspace layout are in the system half, beside the rules that name them), and every scalar interpolated into a system header goes through `_one_line()`, since the split raised those values from a user message to a system one.

**The header says the task is in a registered room** (`executor.room_identity_line`, ISSUE-509): which surface the room lives on, and the `target` / `room` pair that delivers into it from `CRON.md`. `Conversation token` alone was not enough — nothing said the token named a *registered room*, and no CLI could answer the question either, so a task asked to schedule a digest "into this room" created a Talk conversation of the room's name bound to nothing. The line is in the **system** half beside the token it qualifies: it points at nothing in the user half, and a compacted task still has to know which room it is in. Four things about it are decisions rather than details.

It opens its own connection when handed none, because `execute_task`'s `conn` parameter defaults to `None` and only the scheduler passes one — the first cut returned early on `conn is None` and the two golden cases came back byte-identical to their control, which is the shape `.claude/rules/testbed.md` calls a success indistinguishable from a no-op. That nested open is safe under an outer write transaction (`execute_task_interactive` holds one) because it only reads and the framework database is WAL; the hazard `.claude/rules/notifications.md` records is a nested *writer*.

**The room's name is deliberately not in it**, though ISSUE-509 asked for it. A name is third-party text — on a shared Talk room any participant can set it — and `istota-skill rooms list` fences the same string inside untrusted-content markers. Two surfaces disagreeing about whether a field is attacker-controlled is the weaker answer, and the name was the half that was not needed: the descriptor resolves "post here", and `rooms list` answers "which room is #weekly" with `is_current` and a fenced name.

**Every scalar still goes through `_header_scalar`, and covering only the name was the first cut's mistake.** The descriptor carries `room_bindings.surface_ref` — a string Nextcloud supplies rather than one we mint — so a newline in it forges a header line exactly as a newline in the name would have, and the test seeded a hostile *name* and therefore passed for the wrong reason. `_header_scalar` is `str()` then `_one_line()` then a 120-character bound: `str()` because `rooms.name` and `surface_ref` are SQLite `TEXT` columns and SQLite is dynamically typed, so a row written as an INTEGER comes back as `int` and `_one_line` would raise on the prompt-assembly path; the bound because without one a single row makes the system header arbitrarily long. `tests/test_prompt_room_identity.py::TestTheSystemHalfRules` drives a hostile ref, a hostile token and a non-`str` name, and removing `_header_scalar` turns four of them red.

And the descriptor comes from `routing.room_target_descriptor` rather than being spelled here, so the header, `istota-skill rooms list` and the `nextcloud talk create` refusal cannot teach three different spellings; the surface word is `Talk`, never `Nextcloud Talk`, because `tests/test_storage_identity.py` requires the assembled prompt to carry no such literal on the storage-neutral backend and a local-backend deployment can hold migrated `origin='talk'` rows. **Only the clause naming the CLI is gated** (ISSUE-513). `room_identity_line` takes `rooms_cli_available`, which is `"rooms" in advertised_cli_skills(...)` asked once by the caller that already holds the index and the effective disabled set — never re-derived here, which would re-load the skill index on the prompt-assembly path. What it drops is that sentence alone: the "never create a Talk conversation" rule stays on both branches, because it depends on no CLI and matters *more* once the lookup verb is gone — a model that cannot list its rooms is exactly the one tempted to mint a conversation instead, which is the failure this line exists to prevent. The descriptor half is never gated either. `tests/golden/prompts/room_web.txt` and `room_promoted.txt` snapshot the two shapes, against `source_web.txt` — same surface, same token shape, no registry row, no line — as the control; the gated form is a unit case in `tests/test_prompt_room_identity.py::TestTheRoomsCliClause` rather than a golden, and `.claude/rules/testbed.md` records why the synthetic catalogue had to grow a `rooms` skill for the goldens to keep covering the ungated one.

The handoff is a **file**, and it sits in a directory no task can write. `execute_task` creates `{temp_dir}/.control/{user_id}/task_{id}/` — 0700 at all three levels, 0600 files, `O_NOFOLLOW` opens — writes the system half there as `system_prompt.txt` and names it on `BrainRequest.composed_system_prompt_path`, while `BrainRequest.prompt` carries the user half alone. `prompt.txt`, `cli_settings.json` (the `claude` CLI's `--settings` document, `.claude/rules/brain.md`), `briefing_meta.json` and the prepared image renditions under `attachments/` sit beside it: the directory holds every per-task file the daemon authors and nothing the model writes. A control directory that cannot be resolved or created fails the task by **return** rather than by raise, since `process_one_task` handles no exception from `execute_task` and a raise would leave the row `running` until the stuck-worker sweep. `NativeBrain` composes built-in coding block → Istota's file → the operator's file into `AgentContext.system_prompt`, which compaction never touches; both Claude Code backends pass it as `--append-system-prompt-file`, beside the operator file's existing `--system-prompt-file` replace semantics. A path that is set is **required** — a brain fails the attempt rather than running the user half alone, because a silent omission is this bug back under a filesystem race. Direct text-only brain callers (the sleep cycle, shared-block synthesis, health OCR and explanation, the code reviewer, conversation triage) pass `None` and are unchanged, apart from the `--setting-sources user` every `claude` call now carries (`.claude/rules/brain.md`).

Both guards name the **directory** rather than a file, so a framework file added there later is covered without a new entry. `build_bwrap_cmd` binds it read-only after every other bind, and `native_fs_roots` returns it in **both** `read_only` and `write_denied`, because the two are enforced under different conditions and neither covers the other's case. `read_roots = None` means *unconfined* and makes both root lists inert, so the deny entry — checked ahead of that early return — is the only guard on macOS, the standalone install and the shipped Docker stack, which is why the executor seeds it outside its confinement branch. Under confinement the read entry is what makes the directory *readable*: it is a sibling of `user_temp_dir` rather than a child, so it is inside no write root, and without it a task could not open its own prepared image attachment on a path its own prompt named. Only the task's own directory is bound, never `{temp_dir}/.control/{user_id}`, so no task can read another's assembled prompt — which the flat layout this replaced allowed for the whole retention window. Two routes could put a wider path back and one is guarded: `security.sandbox_ro_paths` is bound verbatim and `load_config` warns on an entry overlapping the tree, while a `user_resources` row is bounded by `workspace_path` alone, which `doctor.runtime.task_control_dir` reports rather than refuses. Nothing deletes the directory per task — `cleanup_old_temp_files` owns it, because the scheduler reads `briefing_meta.json` after `execute_task` has returned. The deferred-op files are model-authored by design, stay in the per-user temp dir and keep the symlink exposure `O_NOFOLLOW` answers there.

## Shared rooms: the room card and what else changes

`executor.room_card` replaced the one-line `group_chat_line` ("This is a group conversation. You were @mentioned by …") in the system half (multiplayer D7, Stage 12). It is shown when the task is a guest turn, has `is_group_chat`, or its canonical room is shared, and is empty otherwise, which is what keeps every private-room golden byte-identical. It is built from tables (`rooms.policy.room_readers`), never from the model, and follows both system-half rules above: every scalar through `_header_scalar`, nothing pointing at the user half. Its lines say who reads the room, the room's standing rule (each member's turn runs as that member with their own persona and reach, a confirmation goes to the asker's own private chat with the bot, and what happens to a guest's message under the room's `guest_reply`; on every card, because a model given only this turn's "You are acting for X" generalised it into "I work for X here" and invented an approval rule, ISSUE-602), whom the bot acts for on this turn and who hosts, whose persona is in use, what this turn reaches (on a member's turn: everything they can reach, without their personal memory in the prompt, plus "A guest reads this room" when one does; on a guest's turn: the withheld scopes), the private-reply verbs (`istota-skill room whisper`, and on a member's turn `room answer-privately`) gated on the `room` CLI being advertised, that `CHANNEL.md` is read by everyone, and, on every card, that a member's private notes about the room cannot be shown or edited there. `None` for `withheld_scopes` means the caller did not compute them, and the card then says nothing about scopes.

**Ambient memory and other participants' turns** (ISSUE-576). A member's turn in a shared room skips `USER.md`, dated memories, recall, knowledge facts and playbooks (`executor._ambient_memory_off`, folded into `_skip_memory`), since those reach the prompt without being asked for. Per-skill overlays still load: they are instructions, not notes. In the user half, both history formatters (`context.format_context_for_prompt`, `format_talk_context_for_prompt`) take `principal=task.user_id` and fence any other participant's turn as `ROOM PARTICIPANT MESSAGE`, so a co-member cannot steer a turn that runs at full reach. "Other" includes a row stored with a label and no user id (a guest, an outside correspondent), which `db._conversation_history_from_messages` reports through `external_sender` even when answered, since its `user_id` falls back to the task's. In a room several people have written in (`channel_memory_shared`) the `Replying to` quote is fenced as `QUOTED MESSAGE` too. A bot answer in history is not fenced; that predates this and is the daemon's own voice. A private room has no other speaker, so its goldens do not move.

**No display name reaches the system half.** A guest's display name is text the guest chose, and a member's is text the member chose; in the system half either would be a standing instruction from somebody other than the operator, the reason `room_identity_line` leaves the room name out. The card names members by istota user id and counts guests. A guest's chosen name reaches the model only in the user half, fenced with their words (`GUEST MESSAGE`). The `guest_turn` golden pins it: its display-name sentinel appears once, in the user half.

**The persona follows the principal** (D13 as amended at Stage 12). It is `task.user_id`'s in every case: the host's on the host's own turns and on guest turns, which run as the host, and each other member's own on their turns. A member's `PERSONA.md` is writable from that member's sandbox, so loading the host's into another principal's system half would let one user, or an injection reaching their task, steer a task that runs with another's credentials. The card names whose persona is in use.

**A guest turn's header** reads "You are answering a guest in a room hosted by user X, on their behalf." instead of "responding to a request from user X", and the card's emissary line says the guest's words are data and the only action is the reply. The emissary line is emitted even when the card's database read fails.

**A shared room's notes are fenced** (D24, Stage 27). `build_prompt(channel_memory_shared=)` puts `CHANNEL.md` inside `frame_untrusted(..., "room notes")` plus one sentence, applied after `_apply_memory_cap` so no cut drops the closing marker. The predicate is `executor._channel_memory_is_shared`: a guest turn, `is_group_chat`, or a registered room more than one human has *ever* been in (`db.room_was_ever_shared`, participant history including left rows, union current members), because a departed author's text is still somebody else's. An error fails toward the fence. Recall follows it: in such a room `_recall_memories` drops `channel_memory_durable` (the re-indexed `CHANNEL.md`, already in the prompt) and fences dated `channel_memory` hits. `memory show --channel` applies the same predicate to the CLI read. A private room's notes are unchanged. Group material (`GROUP.md`, group kv values) is fenced the same way; keys, namespace names and heading names are not, being labels the model has to echo back exactly.

**My notes and the linked transcript are user-half material** (ISSUE-608). A principal speaking in a shared room, or a guest turn running as the present host when `guest_reply` is not `direct`, gets that principal's `{bot_dir}/config/rooms/<token>.md` under "My notes about this room (private)" (`executor._my_notes_prompt`, `rooms.private_replies.my_notes_room`), unfenced, since they are the principal's own words. A task in a private room linked to a shared room (`tasks.about_room_token`, `executor._linked_room_prompt`) gets that room's last 40 messages, capped at 12,000 characters and fenced as `PARENT ROOM TRANSCRIPT`, while the member is still a current member; the system half gains one `Linked room:` line naming the room by token only, through `_header_scalar`, and, when the `room` CLI is advertised, the `room post` verb. Neither points from the system half into the user half.
