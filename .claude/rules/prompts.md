# Prompt assembly: the two halves and the control directory

The layer order lives in `AGENTS.md`; the split by authority and its handoff live here. `executor.md` owns the rest of `execute_task()`.

## A task prompt is two halves

**A task prompt is two halves, split by authority** (`executor.ComposedPrompt`, ISSUE-375). `build_prompt` returns `system` and `user`, and the question a layer is sorted on is whether it has to stay verbatim for the life of the task, not how often it changes. Standing instructions — identity, execution constraints, emissaries, persona, workspace layout, tool descriptions, rules, response guidelines, skills changelog, eager skill bodies — are the `system` half. Retrieved memory, knowledge facts, playbooks, conversation and confirmation history, the request and its attachments are the `user` half, which is what a compaction summary carries forward instead. Everything used to travel as one string in the model's first *user* turn, so `NativeBrain`'s first compaction replaced Istota's identity, rules and tool surface with a model-written summary and the task ran on without them. Two rules follow from the split and are held by tests: no line in the system half may point at material in the user half (which is why the four time lines and the workspace layout are in the system half, beside the rules that name them), and every scalar interpolated into a system header goes through `_one_line()`, since the split raised those values from a user message to a system one.

**The header says the task is in a registered room** (`executor.room_identity_line`, ISSUE-509): which surface the room lives on, and the `target` / `room` pair that delivers into it from `CRON.md`. `Conversation token` alone was not enough — nothing said the token named a *registered room*, and no CLI could answer the question either, so a task asked to schedule a digest "into this room" created a Talk conversation of the room's name bound to nothing. The line is in the **system** half beside the token it qualifies: it points at nothing in the user half, and a compacted task still has to know which room it is in. Four things about it are decisions rather than details.

It opens its own connection when handed none, because `execute_task`'s `conn` parameter defaults to `None` and only the scheduler passes one — the first cut returned early on `conn is None` and the two golden cases came back byte-identical to their control, which is the shape `.claude/rules/testbed.md` calls a success indistinguishable from a no-op. That nested open is safe under an outer write transaction (`execute_task_interactive` holds one) because it only reads and the framework database is WAL; the hazard `.claude/rules/notifications.md` records is a nested *writer*.

**The room's name is deliberately not in it**, though ISSUE-509 asked for it. A name is third-party text — on a shared Talk room any participant can set it — and `istota-skill rooms list` fences the same string inside untrusted-content markers. Two surfaces disagreeing about whether a field is attacker-controlled is the weaker answer, and the name was the half that was not needed: the descriptor resolves "post here", and `rooms list` answers "which room is #weekly" with `is_current` and a fenced name.

**Every scalar still goes through `_header_scalar`, and covering only the name was the first cut's mistake.** The descriptor carries `room_bindings.surface_ref` — a string Nextcloud supplies rather than one we mint — so a newline in it forges a header line exactly as a newline in the name would have, and the test seeded a hostile *name* and therefore passed for the wrong reason. `_header_scalar` is `str()` then `_one_line()` then a 120-character bound: `str()` because `rooms.name` and `surface_ref` are SQLite `TEXT` columns and SQLite is dynamically typed, so a row written as an INTEGER comes back as `int` and `_one_line` would raise on the prompt-assembly path; the bound because without one a single row makes the system header arbitrarily long. `tests/test_prompt_room_identity.py::TestTheSystemHalfRules` drives a hostile ref, a hostile token and a non-`str` name, and removing `_header_scalar` turns four of them red.

And the descriptor comes from `routing.room_target_descriptor` rather than being spelled here, so the header, `istota-skill rooms list` and the `nextcloud talk create` refusal cannot teach three different spellings; the surface word is `Talk`, never `Nextcloud Talk`, because `tests/test_storage_identity.py` requires the assembled prompt to carry no such literal on the storage-neutral backend and a local-backend deployment can hold migrated `origin='talk'` rows. **Only the clause naming the CLI is gated** (ISSUE-513). `room_identity_line` takes `rooms_cli_available`, which is `"rooms" in advertised_cli_skills(...)` asked once by the caller that already holds the index and the effective disabled set — never re-derived here, which would re-load the skill index on the prompt-assembly path. What it drops is that sentence alone: the "never create a Talk conversation" rule stays on both branches, because it depends on no CLI and matters *more* once the lookup verb is gone — a model that cannot list its rooms is exactly the one tempted to mint a conversation instead, which is the failure this line exists to prevent. The descriptor half is never gated either. `tests/golden/prompts/room_web.txt` and `room_promoted.txt` snapshot the two shapes, against `source_web.txt` — same surface, same token shape, no registry row, no line — as the control; the gated form is a unit case in `tests/test_prompt_room_identity.py::TestTheRoomsCliClause` rather than a golden, and `.claude/rules/testbed.md` records why the synthetic catalogue had to grow a `rooms` skill for the goldens to keep covering the ungated one.

The handoff is a **file**, and it sits in a directory no task can write. `execute_task` creates `{temp_dir}/.control/{user_id}/task_{id}/` — 0700 at all three levels, 0600 files, `O_NOFOLLOW` opens — writes the system half there as `system_prompt.txt` and names it on `BrainRequest.composed_system_prompt_path`, while `BrainRequest.prompt` carries the user half alone. `prompt.txt`, `briefing_meta.json` and the prepared image renditions under `attachments/` sit beside it: the directory holds every per-task file the daemon authors and nothing the model writes. A control directory that cannot be resolved or created fails the task by **return** rather than by raise, since `process_one_task` handles no exception from `execute_task` and a raise would leave the row `running` until the stuck-worker sweep. `NativeBrain` composes built-in coding block → Istota's file → the operator's file into `AgentContext.system_prompt`, which compaction never touches; both Claude Code backends pass it as `--append-system-prompt-file`, beside the operator file's existing `--system-prompt-file` replace semantics. A path that is set is **required** — a brain fails the attempt rather than running the user half alone, because a silent omission is this bug back under a filesystem race. Direct text-only brain callers (the sleep cycle, shared-block synthesis, health OCR and explanation, the code reviewer, conversation triage) pass `None` and are unchanged.

Both guards name the **directory** rather than a file, so a framework file added there later is covered without a new entry. `build_bwrap_cmd` binds it read-only after every other bind, and `native_fs_roots` returns it in **both** `read_only` and `write_denied`, because the two are enforced under different conditions and neither covers the other's case. `read_roots = None` means *unconfined* and makes both root lists inert, so the deny entry — checked ahead of that early return — is the only guard on macOS, the standalone install and the shipped Docker stack, which is why the executor seeds it outside its confinement branch. Under confinement the read entry is what makes the directory *readable*: it is a sibling of `user_temp_dir` rather than a child, so it is inside no write root, and without it a task could not open its own prepared image attachment on a path its own prompt named. Only the task's own directory is bound, never `{temp_dir}/.control/{user_id}`, so no task can read another's assembled prompt — which the flat layout this replaced allowed for the whole retention window. Two routes could put a wider path back and one is guarded: `security.sandbox_ro_paths` is bound verbatim and `load_config` warns on an entry overlapping the tree, while a `user_resources` row is bounded by `workspace_path` alone, which `doctor.runtime.task_control_dir` reports rather than refuses. Nothing deletes the directory per task — `cleanup_old_temp_files` owns it, because the scheduler reads `briefing_meta.json` after `execute_task` has returned. The deferred-op files are model-authored by design, stay in the per-user temp dir and keep the symlink exposure `O_NOFOLLOW` answers there.
