# Sandbox, task runtime and process boundaries

The boundaries a task runs inside and the modules that build them. `executor.md` owns `execute_task()`; this file owns the environment it hands over. The devbox bullet is in `devbox.md`.

## Security posture

**Multi-user vaults need a sandbox.** With more than one configured user (vault or not), vaults require `effective_sandboxing` or `[security] allow_unsandboxed_multi_user_vaults = true` (default false). `secrets_vault.vault_isolation_refusal` gates passphrase provisioning (CLI and web), sync, status, task credential loading and proxy writes; it withholds cached credentials without deleting rows. Doctor fails and the settings card refuses; with the opt-in doctor still warns (same-uid exposure). Restart services and stop tasks after changing the policy or adding users. Manifest-injected credentials are unaffected.

- **Sandbox** (`bwrap`): per-user filesystem isolation. Linux + bubblewrap is the only supported deployment.
- **Native tools run in the sandbox, one namespace per attempt.** `NativeBrain` spawns `istota.tool_server` per attempt via `build_bwrap_cmd(..., profile=NATIVE)`, places it in the task cgroup from `preexec_fn`, reports its pid via `req.on_pid`; the daemon holds proxies (`session/tools/remote.py`). Before ISSUE-389 file tools ran on daemon threads behind `executor.native_fs_roots` and `Bash` built a namespace per call with the CLI's runtime block. The roots are still enforced: the error-message layer, and the only confinement on unsandboxed shapes. Transport is an inherited socketpair (nothing to replace, no peer to authenticate); `close_fds` keeps it from Bash children. No enable flag, deliberately (it would keep two tool paths); `build_bwrap_cmd` returns the command unchanged where bwrap is unavailable. Rollback is a revert.
- **No databases in the sandbox.** `build_bwrap_cmd` ends by masking `db_path.parent` and `module_db_root()` with an empty read-only tmpfs, last so no earlier bind shows through, with `--remount-ro` and `--disable-userns` (plus required `--unshare-user`) where supported: a writable mask lets `sqlite3` create a zero-byte file that reads as corruption, and a tmpfs can be unmounted from a nested userns. So keep `sandbox_ro_paths` narrow; the mask does not make a broad entry safe. Nothing binds the framework DB (`sandbox_admin_db_write` retired), `sandbox_ro_paths` defaults to `[]`, `native_fs_roots` matches. Host-side skill CLIs scoped by `ISTOTA_USER_ID` are the per-user boundary; masks are defence in depth.
- **Session logs are unbound: an absence, not a guard.** Native transcripts (assembled prompt, `USER.md`) go to `{db_path.parent}/logs/{user_id}/` (`/data/db/logs` on Docker), bound nowhere, in no `native_fs_roots` root. Kept out by `security.sandbox_ro_paths` defaulting to `[]` (its old `/srv/app` default exposed every DB) and, on standalone, no `user_resources` row naming it (`workspace_path` equals `db_path.parent` there). The mask backs this only on Ansible: shipped Docker lacks `seccomp:unconfined` / `systempaths=unconfined` so runs unsandboxed (`native_fs_confinement_active` gates on `effective_sandboxing`), and standalone `_mask_dir` refuses (all under `~/.istota`). `doctor`'s `runtime.session_log_dir` asks `executor.mask_shadowed_by`, reporting availability (`executor.effective_sandboxing`, not `sandbox_enabled`, ISSUE-381) then placement; under `probe=False` it uses `effective_sandboxing_if_known` and reports unestablished. Never `user_temp_dir`. Tasks read transcripts via `istota-skill tasks transcript`.
- **One admin's repos are not in another's sandbox.** `build_bwrap_cmd` binds `{repos_dir}/{user_id}` (holding `{namespace}/{project}.git`), never the root; `native_fs_roots` matches; `DEVELOPER_REPOS_DIR` comes only from developer `setup_env`; `skill_host_paths.resolve_under_repos` scopes `--worktree`. The cache is derived at `{repos_dir}/{user_id}/.package-caches` (same mount as a venv for `link(2)`; retired the ISSUE-319 sibling masks). **Gated on `sandbox_cache_is_derived`, the repos bind's condition including `is_admin`; a boundary** (ISSUE-320): the later repos bind buries a symlink swapped in between check and `mount`. Non-admins get the fallback root or none; no separate cache write root in `native_fs_roots`. `repos_relocate.py` moves old trees.
- **Config dir out of the sandbox.** Prompt-text files and `config.toml` live in `config/`, never bound. Exception: under `custom_system_prompt`, `config/system-prompt.md` alone (`custom_system_prompt_path`), `CLAUDE` profile only, since the CLI opens it via `--system-prompt-file`. `NATIVE` binds none; `NativeBrain` reads it in the daemon.
- **Network proxy**: `--unshare-net` + CONNECT proxy on a Unix socket, `host:port` allowlist. TLS interception only for credential-bound hosts in the task snapshot, when the broker is enabled.
- **Skill proxy.** Strips secret env vars; CLI calls go through a Unix socket injecting credentials server-side, decoupled from skill selection. Required wherever the sandbox is (`istota-skill` refuses under `ISTOTA_SANDBOXED`). DB paths (`ISTOTA_DB_PATH`, manifest `proxy_only`) go to the proxy only. Requests: `credential` (manifest lookup for git and forge helpers), `vault_list` / `vault_credential` (map from `task_env`, capped by `vault_fetch_limit_per_task`). `credential_shim.py` goes to `{user_temp_dir}/.istota/istota-credential` (0700) on the model's PATH only, never `proxy_base_env`'s; `.istota` is re-bound read-only after the workspace (like `.developer`). The shim is a convenience, not a gate. **The socket gates which task asks** (ISSUE-550): 0600 stops other uids, not other tasks. The proxy serves only kernel-reported peers descending from pids its task registered: the brain child via `on_pid` (to `authorize_pid` first) and spawned skills (`peer_process.reporting_pid`, revoked on exit), pinned to start time against pid cycling. Narrows rather than closes cross-task access on unsandboxed multi-user hosts; `security.proxy_peer_check` warns. Env nonce rejected (same uid reads env). A brain skipping `on_pid` gets every skill call refused.
- **Host paths in skill CLIs.** A model-chosen host path is an arbitrary read or write unless scoped. **The disposition sits on the argument** (ISSUE-447): `skills/_hostpath.host_path` stamps it; `skills/_cli.parse_and_resolve` resolves before dispatch and writes back; refusal is `reason: host_path_refused`. Modes by where bytes end up: `READ` (deferred dir, own workspace, own channel, `{mount}/Talk`, mirroring binds); `WRITE` (minus read-only roots); `EGRESS` (workspace and deferred dir, for content mailed, indexed, uploaded or persisted); `REPO`, `REMOTE`, `NOT_A_PATH` resolve nothing. Never the mount whole; symlinks rejected; no directory created at parse. `write_resolved` makes the parent at write, `O_NOFOLLOW`; `feeds export-opml` uses `_ensure_parent` since a Click CLI opens the file.
- **Coverage.** `tests/test_skill_host_paths_coverage.py` builds every parser (`build_parser`, Click `build_cli`) and requires each path-shaped argument to have a stamp or registry record (`UNSCOPED` is gone). `tests/test_skill_host_paths_refusals.py` drives each resolving stamp for refusal and acceptance. **`google_workspace` is bounded by an argv scan, a weaker claim**: `gws` cannot be walked, so `scan_argv` classifies tokens (absolute, `~`, `..`, existing relative, `=` split, short-flag tail, leading `@`) and resolves them under the read rule (`drive +upload` takes a Talk attachment). A not-yet-existing relative token passes; cwd is the workspace.
- **Nothing narrows what the daemon itself may read**; argument scoping is the only layer. Cut: a systemd read allowlist (leaves `{istota_home}` and the mount readable) and a bwrap `SandboxProfile.SKILL` (needs a conditional DB mask, `config/` bound, an ISSUE-390 carve-out, a per-skill table).
- **No Docker API in the sandbox.** No socket bound, no `DOCKER_HOST`; a `docker` binary fails at connect. The per-user `/var/run/docker.sock` proxy is retired (`docker exec` through it lost exit status, forcing the exec transport).
- **Native WebFetch** (`session/tools/web_fetch.py`): daemon netns, outside the CONNECT allowlist, credential-free (`trust_env=False`), SSRF-hardened (each resolved IP checked per hop and pinned, GET/text only, caps, untrusted delimiter). **Every user** (ISSUE-449): the `[brain.native.web_fetch]` egress policy bounds all alike; `admin_only = true` restores the gate (read by `build_allowed_tools`, not mapped onto `WebFetchPolicy`). `require_url_provenance` as non-admin default rejected: its corpus is the user half, so WebSearch-then-read fails. See `brain.md`.
- **Deferred DB**: sandboxed tasks write JSON to temp; the scheduler applies it after success. Identity (`user_id`, `conversation_token`) from the task, never the JSON. Subtasks admin-only, capped by `max_subtasks_per_task`, `max_subtask_depth`, `max_subtask_prompt_chars`.

### The credential vault

The one thing deliberately inside a sandbox; bounded by the file, not the encryption. A `.kdbx` in `{bot_dir}/vault/` plus a `vault/passphrase` row, or an operator `[users.<id>] vault_path` (outranks the folder), sits in the read-write workspace: a task can read, copy, delete or overwrite it, not open it (passphrase row behind the DB mask; master Fernet key in no subprocess env). The working route would be a manifest declaring the pair (`derive_skill_credential_map`); `tests/test_secrets_vault.py::TestNoSkillManifestDeclaresThePassphrase` refuses one by parsed `(service, key)`.

With reveal enforcement off it is a flat namespace (`apply_vault` into `vault_entries`) an injected task can read whole (spec §5). Bounds, only the first a boundary:

- **The file is the consent decision.** Reachable means under a top-level `istota` group (case-insensitive, stripped) or created under `generated/`. **No such group means the file is read in full**, like typing it into settings (why removing `vault_services` was safe). Unscoped reads are reported on the card, `istota secret vault-status` and a one-shot notification.
- **A skill takes the name, not the value.** `skills/_credref.py` stamps, `parse_and_resolve` resolves before dispatch, the value goes daemon to browser without crossing the namespace (`browse interact --fill-credential`). Prefer this.
- **`[security] vault_fetch_limit_per_task`** (10, `0` unlimited) per attempt, counted whether or not the name resolves.

**`vault_create`** adds an entry to the user's KDBX (absolute `vault_path` too): create-only under `generated/`, refuses name collisions, daemon-private lock. `[security] vault_writes_per_task` 3 per attempt including refusals, `0` disables. Password generated host-side; the reply carries names and username only. Each create raises an `action_needed` notice. Residual: an open password manager can save over it undetectably.

**The generated passphrase protects the file, not the namespace** (`istota secret ensure --service vault --key passphrase --generate`; under 32 characters refused). It bounds the offline case and entries outside the group; do not read §6 as protecting credentials from the model. Any sandbox process can speak the proxy protocol. `run VAR=name -- cmd` injects silently; `get` returns the value (absent from the prompt, logged at WARNING). Against accident, not intent.

**Absolute `vault_path`** removes the file exposure, not the by-name read (`storage._sandbox_writable_roots` refuses one under workspace, `temp_dir` or `repos_dir`). TOML-only: a user-chosen path would be a daemon read of any file. The card writes a **filename** checked by membership in `storage.list_vault_files`; `storage.vault_location_for` resolves path, stored filename, only file, else refuses. The name lives in reserved `_vault_file`; the path is not on `user_profiles` (any profile-writing verb reaches it). `user_vault_config` (with `vault_services`) is dropped by `db._migrate_drop_retired_vault_table`. `Config.vault_path_for` is the only raw-field reader (`tests/test_vault_removal.py`). Deleting the file is a notified DoS; an older copy is a real rollback. Docs: `docs/deployment/security.md`, `docs/configuration/credentials.md`.

## Shared rooms and groups in the mount plan

A turn runs with its sender's reach (ISSUE-576). `room_scopes.withheld_for_task(conn, task)` is the one derivation: every scope on a guest's turn, every scope on a task in a shared room no member asked there (no origin surface, as for cron, briefing, subtask, CLI; or a stored turn whose author is not the task's user, as for an outside correspondent's email continuing the room's thread), nothing otherwise, a member's turn with a guest present included. A read error on the second case withholds everything. Read by `effective_disabled_skills`, the proxy's `cli_skills`, `derive_authorized_skills` and identity env (`reach_index`), setup-env hooks (env dropped), and the mount plan. A member's turn in a shared room loses only ambient memory, in prompt assembly (`.claude/rules/prompts.md`). Per-room grants, `!room share` and `[rooms] shared_room_data_policy` are gone; `room_data_grants` is dropped by migration. Rules: `transport.md` ("Multiplayer rooms"), `docs/features/shared-rooms.md`.

What a restricted task gets:

- **No workspace without `files`**: `{mount}/Users/{user_id}` and per-resource mounts unbound. Without `developer`, repos and cache go too, dropped in `resolve_sandbox_cache_dir` so bind and `UV_CACHE_DIR` agree (ISSUE-320).
- **Own temp dir**: `{temp}/{user}/emissary-task-<id>` for a guest, `room-task-<id>` otherwise, also `ISTOTA_DEFERRED_DIR`, since a guest-planted op file in the persistent per-user dir would replay at the host's authority. `executor.task_deferred_dir` reads the choice from disk (restriction can change before drain); all deferred and `email_output` readers use it. A symlink there fails the task by return.
- **No Talk bind**: the task's attachments are copied to `{control_dir}/room-attachments` (read-only, `O_EXCL | O_NOFOLLOW`), `task.attachments` names copies in memory only; `image_bind_roots` drops Talk.
- **CLAUDE profile binds no `~/.claude/projects`, `debug`, `todos`** (earlier sessions' JSONL holds `USER.md`).
- **`ISTOTA_WITHHELD_SCOPES`** is in the proxy base env only. `env_host_roots` drops the workspace without `files` and Talk when anything is withheld; `skill_host_paths.memory_refusal` refuses memory dirs; the `skills` guard unions it with `withheld_for_task` over `ISTOTA_TASK_ID`; nextcloud `_scoped` refuses file and share verbs without `files`, and memory paths without `memory`, after collapsing a leading `//`. Without `memory`, `files list --depth` and `files search` drop entries inside memory dirs. Residual: `share list` (`--subfiles` or no path) and `files trash list` still show them.
- **Talk writes check the live roster**: `nextcloud talk send`, `share-file`, `rename`, `describe`, `invite`, `leave`, `delete` refuse unless participants are caller plus bot; posting into the task's own room is exempt, changing a shared room never; `invite` takes only the caller; an unfetchable roster refuses. Unchecked outside a task.
- **Vault withheld whenever anything is**: `vault_credentials={}`, `vault_write_limit=0`, no prompt line. Calendar discovery skipped without `calendar`.
- **`Groups/<id>`**: each group in `room_scopes.task_group_ids` bound read-write as `nextcloud_group_dir` after the channel bind, sorted, de-duplicated, via `user_scope.scoped_user_dir`. `Groups/` never bound. Empty for a guest turn, stored-mixed turn, any guest/agent/unmapped participant, no recorded readers, or readers the members do not cover; `rooms.group_id` narrows. `project_fs_roots` carries it. `ISTOTA_TASK_GROUPS` (proxy env only) gates kv/memory `--group` (`skills/_group_access`, whole-id); deferred kv re-derives from the task row.

**Without bwrap none of this confines**: Docker, macOS and standalone strip prompt, skills, allowlist and env, but tools can still read the workspace; `security.room_scope_confinement` warns. Witness: `tests/smoke/test_sandbox_shared_room.py` with a private-room control; the default suite reads argv only. The memory masks, the bot-directory self-bind and `IDENTITY_GUARD` (Stage 28) were removed with the grants: they fired only for `files` granted without `memory`, which no turn can be any more.

## task_env.py

`build_task_runtime`: the model env, the credential split (clean / proxy-only / credential), the `SkillProxy` and `NetworkProxy`, and the read-only bind list, as a `TaskRuntime`. **Context managers are built here, entered by the caller**: they must span primary, reroute and fallback, so the `ExitStack` stays in `execute_task` around `run_with_failover`.

Load-bearing orderings: `proxy_base_env` is snapshotted before `ISTOTA_SANDBOXED` is set (skills run host-side); proxy-only split runs first, credential split on the residue (a var declared both ways stays proxy-only); `HOOK_PATH_PREPEND_KEY` is consumed after the snapshot (task-temp on host PATH is code execution); ISSUE-410 top-ups run after both splits.

**ISSUE-410 top-ups**, split by whether an uninterested CLI can be harmed. Trust stores only add a CA: `skill_cli_tls_env` puts `SKILL_CLI_TLS_VARS` (with `CURL_CA_BUNDLE`, as `forge_cli._CARRY_EXACT`) in the shared snapshot. Proxy URLs redirect traffic (even loopback, e.g. `browse` via httpx `trust_env=True`) and can carry userinfo, so `skill_model_reachability` routes `SKILL_MODEL_REACHABILITY_VARS` (proxy triple, `ANTHROPIC_BASE_URL`) through the per-skill map and `_PROXY_LOOKUP_BLOCKED` gains them. Gap-fillers, never overrides (`credential_env` keeps `sensitive` names out); `derive_credential_set` is index-wide, so one `sensitive` `SSL_CERT_FILE` removes it for all. Open: `feeds` egress proxy. Inside `skill_proxy_enabled` only.

The network-proxy gate asks `config.security.sandbox_enabled` (asked for), the sandboxed marker `effective_sandboxing` (got); they differ on Linux without bwrap, so do not unify. `executor` is imported at function scope (cycle; keeps `monkeypatch.setattr(executor, "_bwrap_available", …)` working).

## claude_runtime_env.py

What a task env carries only because the outer process is the `claude` CLI (`CLAUDE_CODE_OAUTH_TOKEN`), and the copy that removes it. `build_clean_env` sets it for every task; under `NativeBrain` it has no reader and one exit (Bash `echo` to whatever provider native uses, ISSUE-390). Env counterpart of ISSUE-389's Claude-only mounts.

Stripped at `NativeBrain._hello_payload` (Bash children), `NativeBrain._start_tool_server` (children read `/proc/<pid>/environ`), and `execute_task`'s `proxy_base_env` (no manifest declares it). **Scoped exception** (ISSUE-409): `executor.SKILL_MODEL_CALLERS` (`code_review`, which spawns `claude`) get it plus `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` copied into their per-skill map by `skill_model_credentials`; a copy, since it also authenticates the task's `ClaudeCodeBrain`. `_PROXY_LOOKUP_BLOCKED` gains these names.

A name list, not a `CLAUDE_*` prefix (would eat `passthrough_env_vars`), guarded over `build_clean_env`'s keys. **Copies, never mutates** `req.env` (carried across a `native -> claude_code` fallback). **`None` and `{}` differ**: `ToolEnv.subprocess_env` reads `None` as inherit-daemon-env, so the caller applies `or None` to the input. Other credentials leave via `_split_credential_env` under `skill_proxy_enabled`; proxy off with sandbox on warns (ISSUE-393). stdlib-only: `brain/native.py` cannot import `executor`.

## tool_server.py

`python -m istota.tool_server --fd N`, one per **task attempt**, via `build_bwrap_cmd(..., profile=NATIVE)`, placed in the cgroup from `preexec_fn`. Builds one `ToolEnv` from `hello` and binds the six core tools (`build_default_tools`) (ISSUE-389). Holds no image library (see `image_sniff.py`) and must not import `istota.skills` (`tests/test_tool_server_env.py::TestTheServerDoesNotImportTheSkillsPackage`; why `git_hardening.py`, `forge_bin.py`, `untrusted.py` sit at the package root).

- **Wraps nothing**: nested bwrap under `--unshare-user --disable-userns` fails, so `ToolEnv` lost the field.
- **Places nothing**: membership is inherited at fork; `cgroup.procs` is unbound.
- **Merges `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` from its own env** into `subprocess_env`, since the wrapper `exec env`s them onto this process and the frame env came from the bridge-less daemon. `NO_PROXY` is deliberately empty, so the merge tests presence; the wrapper wins collisions (the loopback bridge is the only reachable proxy).

Nothing raises past `main` (sends `fatal`); frame contents are never logged.

## tool_server_protocol.py

stdlib-only, one `ProtocolError`. 4-byte big-endian length plus UTF-8 JSON; `MAX_FRAME_BYTES` (32 MiB) enforced on both ends. Messages: `hello` / `call` / `abort` / `shutdown` down, `ready` / `update` / `result` / `fatal` up. `ToolResult.details` does not cross (only `agent/loop.py` reads it); content blocks are plain dicts. `FrameDecoder.close()` raises on leftover bytes: a missing result is a broken server, not an unmade call.

## task_cgroup.py

A cgroup v2 group per task (A6): `<unit cgroup>/task-<id>-<attempt>/` with `memory.max`, `pids.max`, `cpu.max`. A sibling of the daemon's `supervisor/` leaf (v2 forbids controllers under a process-holding cgroup). `resolve_root` takes the last `.service`/`.scope` (the first is `user@N.service`). A successful `memory.max` write is the delegation proof, so startup calls `probe()`, not `resolve_root`. Placement is `preexec_fn` since bwrap forks during setup (ISSUE-285): parent opens `cgroup.procs`, child writes `0`, `verify_placement` reads back. `place()` only for TmuxClaudeBrain. `destroy` writes `cgroup.kill` on `EBUSY` (5.14+); `read_events` names an OOM kill before `rmdir`. Fails open without `Delegate=`, said at startup. stdlib-only, never raises.

## user_scope.py

Scoping a user id under a root (ISSUE-402). A plain join is not a check: `PurePath` drops `""` and `.` (giving every user's parent), an absolute component replaces the root, `..` is the parent on disk. **Two checks**: lexical (component became a child) and resolved (`..`, symlinks); `"."` passes resolved and only lexical sees it. **Validated resolved, returned as written**, since `sandbox_plan._bind` uses the string as the namespace destination. Returns `None`, never the shared root; callers drop the bind, root or entry. `is_scopable_user_id` is the lexical half without a root (`db.create_task` defaulted `user_id` to `""`); it refuses `.`/`..` only as whole values. Consumers: `sandbox_plan.build_mount_plan` (bind and per-resource skip), `executor.image_bind_roots`, `executor.get_user_repos_dir` (the rule since ISSUE-319), `Config.workspace_root`, the `memory` skill's `_user_id`, `db.create_task`, `skill_host_paths.workspace_roots` (which replaced `memory_search._indexable_roots`). `project_fs_roots` projects the same plan. stdlib-only, never raises.

## skill_host_paths.py

**One rule, one implementation, two derivations** (ISSUE-447). Containment: `path_under_roots` / `resolve_in_roots`. Roots: only `workspace_roots`, which scopes `{mount}/Users/{user_id}` via `user_scope.scoped_user_dir`, guards the conversation token, and drops what it cannot scope. Skill CLIs derive from their env (`env_host_roots`, `resolve_host_path`); the daemon, with no task env, passes mount and user id explicitly (`scheduler_deferred._source_path_allowed`, `outbound_drafts._confined_attachment`). **Same implementation, different roots**: deferred replay has no token or Talk; drafts are owner-workspace only (released hours later); so `talk` and `channel` are per-caller switches. Per-argument dispositions live in `skills/_hostpath.py`.

`scheduler_deferred`'s `import_csv` arm read `source_path` unchecked on every shape (any daemon-readable file into the health DB); it now uses `_resolved_source_path`. Replay is a boundary everywhere, so `health upload` / `import-csv` / `attach-document` are `EGRESS`, matching replay's accepted set.

**A spawner passes task identity, or every path is refused.** `whisper`'s `out_of_process` spawn lacked `ISTOTA_USER_ID` and `_pre_transcribe_attachments` logs only at debug. `--trusted-caller` and daemon-detection rejected. `executor._audio_in_reach` stages out-of-roots attachments (only `{mount}/Talk/<name>` of four shapes is in roots) into the task temp dir first.

**Derived paths are contained by construction; writability is not** (still `write_resolved`). A read root is not a write root (ISSUE-453): `_save_destination` re-resolves `whisper transcribe --save` against `_hostpath.write_roots()` before transcribing (Talk dropped, channel kept); guard `tests/test_skills_whisper.py::TestTheDerivedSaveDestinations`. Content-supplied components are re-resolved: `email attachments --dest` resolves each MIME name under the destination alone (`resolve_in_roots`, not `resolve_host_path`), skipping traversals.

`resolve_under_repos`: `developer_repos_root()` re-derives `DEVELOPER_REPOS_DIR`'s scope from `ISTOTA_USER_ID`, `None` on mismatch or absence. Empty allowlist refuses everything. stdlib plus `user_scope`.

## kv_namespaces.py

`istota_kv` namespaces with a leading `_` are framework state the model may not touch: curation audit trail and fingerprints (`memory/curation/audit.py`), `_provisioned_rooms` (default-room tokens and invite outcome, ISSUE-342/408, so a task cannot re-point a deploy), `_avatar_import` and `_session_log_sweep` (doctor state), all `shared_kv`; `_vault_sync` (per-user, read by the separate web unit); `_vault_file`, `_credential_grants`, `_credential_fields`. A prefix, not a list. **Two enforcement points**: `skills/kv` `main` before any verb (behind `parse_and_resolve`, so a bad `--value-file` answers `host_path_refused` first) and `scheduler_deferred` on apply (sandboxed tasks write op files). `kv namespaces` hides them. Defence in depth; the boundary is the unbound DB. `is_reserved_namespace` takes `object`. stdlib-only.

## git_hardening.py

`-c` overrides stopping repo config running programs (`core.fsmonitor`, `diff.external`, `gpg.*`, plus output-reshaping keys parsers need). Repo-local config escapes `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL` and is model-written under `developer.repos_dir`. Extracted from `skills/code_review/engine.py` (still re-exported) so `worktree_reaper` avoids importing `istota.skills` (~190ms); same reason as `forge_bin.py` and `untrusted.py` (ISSUE-512). No imports.

## git_remote_scrub.py

Strips credentials from git configs under `developer.repos_dir` (ISSUE-270). Callers: developer `setup_env` on `{repos_dir}/{user_id}` before binding (cache passed as `skip`), `worktree_reaper` on the root. `_MAX_DEPTH = 4` (bare clone at depth 2 per user, 3 from root). Uses `git config` (`--includes` + `--show-origin`, `-z`, `--fixed-value`), never the file. Covers keys (`url.<base>.insteadOf`), `config.worktree`, `http.*.extraheader`. Detects userinfo passwords and forge-token prefixes, not a bare `@`. Never raises, never logs values, reports what it could not remove.

## forge_cli.py

`gh` / `glab` wrapper for sandbox and devbox (`docker/devbox/lib/istota_forge_cli.py` is a byte copy via `scripts/sync-devbox-lib.sh`). Forge from argv[0], code-owned deny policy, then a placeholder when the sandbox policy enables the broker, else a token from the available credential socket, then exec. Git helpers share the broker setting. Broker mode never falls back to raw values; runtime logs that placeholders cannot authenticate. The model env drops forge tokens in broker mode even with the skill proxy off. Devbox policies never enable broker mode. Policy, `real_bin`, URL and config dirs come from the file beside the executing copy, never `os.environ`. No URL resolved means refuse, not a public host.

## shell_exec.py

`shell_argv(command)` with `pipefail`, for callers trusting exit status: native Bash, CRON `command:` rows (auto-disable), heartbeat `shell-command` (cf. ISSUE-307). `bash` is named, not probed; fallback `/bin/sh -c`, logged once. An interpreter swap: bash sources `$BASH_ENV` (stripped by `executor.build_stripped_env`).

**`pipefail_env()`** (ISSUE-321) returns `{"SHELLOPTS": "pipefail"}`, applied last by `executor.build_clean_env`, for the Claude Code CLI's own `bash -c` that `shell_argv` cannot reach. `SHELLOPTS` cannot source a file (`pipefail:$(touch /tmp/x)` is rejected). `_SHELL_STARTUP_ENV_VARS` (`BASH_ENV`, `SHELLOPTS`, `BASHOPTS`) are filtered from both env builders first. Inherited, so nested bash gets it; dash does not. Cron and heartbeat keep flag depth (operator-authored). `is_sigpipe_failure`: a SIGPIPE-killed cron row is failed, not retried (retry re-runs the producer). `SIGPIPE_EXIT` / `SIGPIPE_NOTE` annotate 141. A non-final stage exiting non-zero to report (`grep -c x f | wc -l` returns 1) has no marker; documented. stdlib-only, never raises.

## peer_process.py

Peer identity on a Unix socket and descent from roots (ISSUE-550). `peer_pid`: `SO_PEERCRED` (translates `--unshare-pid` pids) or `LOCAL_PEERPID`. `parent_pid`: `/proc/<pid>/stat` after the last `)`, or `proc_pidinfo(PROC_PIDTBSDINFO)`. `start_time`: field 22, or `pbi_start_tvsec`/`pbi_start_tvusec`. `descends_from` takes `{pid: start}`, needs both to match, refuses on unreadable links and at pid 1. `reporting_pid` is a `preexec_fn` sending the child pid down a close-on-exec pipe, reader joined on exit; runs after `task_cgroup.placement`. Other platforms answer `None`, so all are refused (`security.proxy_peer_check` FAIL). `PeerRoots` serves both proxies; the network proxy checks before reading CONNECT, and brain children are registered with both even with the skill proxy off. No roots, no access; per connection, so an admitted tunnel lasts until closed. stdlib-only, never raises.

## process_group.py

`kill_process_group(pid, sig)`: signal the group, or only the process when it leads none (a non-leader shares the daemon's group). The streaming CLI child and tmux panes lead groups; `ClaudeCodeBrain`'s non-streaming child does not. Used by ClaudeCodeBrain's streaming kill paths, `!stop`, the web cancel endpoint, scheduler and native-bash timeouts. Never raises (called from a `threading.Timer`).

## Credential grant snapshots

`credential_broker/grants.py`: policies, room scopes, per-task revisions. Missing grant denies; new grants have scheduled use off. `build_task_runtime` freezes admission under `BEGIN IMMEDIATE` (or the caller's transaction); `tasks.credential_grants_initialized` records even an empty snapshot so retries add nothing. Live checks: ownership, scope, scheduled ancestry, revision, binding, presence; forge checks also need `is_admin(user_id)` and `developer.enabled` from live `Config`. Enforced by the intercepting proxy (`check_credential_grant`) and the private channel (`check_credential_use`, grant only). Forge bindings are per user, written on the settings identity gate; a shared-room task without `developer` is kept out by the snapshot, not by deleting rows (which broke concurrent tasks).

Reserved KV `_credential_grants`: `granted_existing` (one-time upgrade action), `revision:<name>` (kept after deletion so a recreated grant cannot revive an old snapshot; policy edits advance it), `allow_http:<name>` (explicit, default off; HTTP bindings keep `http://`). `_credential_fields` maps imported fields to their vault entry (from the vault parser, not suffixes). Deleting a vault credential deletes its grant and room rows in one transaction; task retention and room deletion delete task grant rows explicitly (no FK cascades).

## Credential broker CA

Grants allow every HTTP method; legacy `credential_grants.methods` is kept for compatibility, neither exposed nor enforced. Exact host and port, auth-header restrictions, the HTTP override and live revocation still apply.

`credential_broker/ca.py`: opt-in CA under `{db_path.parent}/credential-broker` (`0700`, atomic `0600` P-256 key plus ten-year cert, cross-process lock). Corrupt or insecure records fail closed; delete `ca-key.pem` and restart to rotate. Setup rejects a location under any sandbox bind, masked or not. Leaves: exact SANs, 24 hours, bounded cache, loaded via a temp private file removed at once. HTTP/1.1 only; SNI must equal Host; upstream verified with the daemon trust context.

`build_task_runtime` writes system roots plus the CA into the read-only control dir. `TaskRuntime.sandbox_env` reaches only `sandbox_plan`'s `exec env` wrapper (never task, proxy or daemon env); the tool server passes it to Bash via `merge_proxy_env`. Node gets the CA as an extra root; others use the bundle. Broker off: nothing created. No effective sandbox: no broker trust, and setup warns.

`credential_broker/intercept.py` intercepts only snapshot-bound hosts (others stay raw TLS); absolute-form HTTP gets the same checks for allowlisted snapshot destinations. The HTTP override never downgrades HTTPS. Per request the h11 loop checks grants, replaces placeholders only in allowed auth headers (Basic decoded first), and refuses them in URLs or the body prefix. Small responses and headers are scrubbed; large ones stream unscanned. Encoded bodies, encoded authenticated responses, trailers and upgrades are refused. Audit never holds values. Off by default; legacy fetch paths remain.

## Private skill credential channel

Each skill invocation gets a socketpair via `ISTOTA_CRED_FD` / `pass_fds`, never the model; the skills package marks it close-on-exec before loading skill code. `_credref` resolves at parse time over a per-name duplicate. The proxy accepts only credential reads there, sets provenance itself, and charges the attempt budget. With the broker on it checks the grant (room scope, `allow_scheduled`, revision), refusing `credential_not_granted` or `credential_changed`; a grant read error refuses. Names created this attempt by `vault_create` are exempt (`_created_names`, in memory) for create-then-fill; later tasks need a grant. Public reads follow the reveal policy, not grants. Values come from the live lookup.

Both ends are closed and the reader joined on success, timeout or spawn failure. An invalid fd refuses without falling back; callers with no fd use the public socket, under the reveal policy.

## Public credential reveal enforcement

`SkillProxy._serve_vault_credential` charges the budget and checks presence before reading live `credential_bindings.revealable`; under enforcement permission and value are read in one transaction. Only the private dispatcher sets `trusted_skill=True`; public `mode` or trust claims carry no authority. Unmarked public reads log `credential_reveal action=would_refuse reason=credential_brokered` at WARNING, or return `credential_brokered` with `[security.credential_broker] enforce_reveal = true`. Predicate `CredentialBrokerConfig.reveal_enforced` also needs `enabled` (no placeholders otherwise, so every git and forge read would fail; `load_config` warns). Missing metadata means no reveal; names via `label_for_display`, values never logged.

Covers `get`, both `run` forms, raw socket clients, and the public manifest `credential` branch (manifest vars and forge tokens have no reveal marker). Host-side injection and the private fd are unaffected; `list`, `placeholder`, `new` unchanged. Enable after a week with no would-refuse events; nothing enables it automatically. Devbox credentials are outside this policy.
