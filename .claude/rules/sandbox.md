# Sandbox, task runtime and process boundaries

The boundaries a task runs inside and the modules that build them. `executor.md` owns `execute_task()`; this file owns the environment it hands over. The devbox bullet is in `devbox.md`.

## Security posture

**Multi-user vaults need a sandbox.** With more than one configured user (vault or not), vaults require `effective_sandboxing` or `[security] allow_unsandboxed_multi_user_vaults = true` (default false). `credentials.names.vault_isolation_refusal` gates import/export, task credential loading and proxy writes; it withholds cached credentials without deleting rows. Doctor fails and the settings card refuses; with the opt-in doctor still warns (same-uid exposure). Restart services and stop tasks after changing the policy or adding users. Manifest-injected credentials are unaffected.

- **Sandbox** (`bwrap`): per-user filesystem isolation. Linux + bubblewrap is the only supported deployment.
- **Native tools run in the sandbox, one namespace per attempt.** `NativeBrain` spawns `istota.sandbox.tool_server` per attempt via `build_bwrap_cmd(..., profile=NATIVE)`, places it in the task cgroup from `preexec_fn`, reports its pid via `req.on_pid`; the daemon holds proxies (`session/tools/remote.py`). Before ISSUE-389 file tools ran on daemon threads behind `executor.native_fs_roots` and `Bash` built a namespace per call with the CLI's runtime block. The roots are still enforced: the error-message layer, and the only confinement on unsandboxed shapes. Transport is an inherited socketpair (nothing to replace, no peer to authenticate); `close_fds` keeps it from Bash children. No enable flag, deliberately (it would keep two tool paths); `build_bwrap_cmd` returns the command unchanged where bwrap is unavailable. Rollback is a revert.
- **No databases in the sandbox.** `build_bwrap_cmd` ends by masking `db_path.parent` and `module_db_root()` with an empty read-only tmpfs, last so no earlier bind shows through, with `--remount-ro` and `--disable-userns` (plus required `--unshare-user`) where supported: a writable mask lets `sqlite3` create a zero-byte file that reads as corruption, and a tmpfs can be unmounted from a nested userns. So keep `sandbox_ro_paths` narrow; the mask does not make a broad entry safe. Nothing binds the framework DB (`sandbox_admin_db_write` retired), `sandbox_ro_paths` defaults to `[]`, `native_fs_roots` matches. Host-side skill CLIs scoped by `ISTOTA_USER_ID` are the per-user boundary; masks are defence in depth.
- **Session logs are unbound: an absence, not a guard.** Native transcripts (assembled prompt, `USER.md`) go to `{db_path.parent}/logs/{user_id}/` (`/data/db/logs` on Docker), bound nowhere, in no `native_fs_roots` root. Kept out by `security.sandbox_ro_paths` defaulting to `[]` (its old `/srv/app` default exposed every DB) and, on standalone, no `user_resources` row naming it (`workspace_path` equals `db_path.parent` there). The mask backs this only on Ansible: shipped Docker lacks `seccomp:unconfined` / `systempaths=unconfined` so runs unsandboxed (`native_fs_confinement_active` gates on `effective_sandboxing`), and standalone `_mask_dir` refuses (all under `~/.istota`). `doctor`'s `runtime.session_log_dir` asks `executor.mask_shadowed_by`, reporting availability (`executor.effective_sandboxing`, not `sandbox_enabled`, ISSUE-381) then placement; under `probe=False` it uses `effective_sandboxing_if_known` and reports unestablished. Never `user_temp_dir`. Tasks read transcripts via `istota-skill tasks transcript`.
- **One admin's repos are not in another's sandbox.** `build_bwrap_cmd` binds `{repos_dir}/{user_id}` (holding `{namespace}/{project}.git`), never the root; `native_fs_roots` matches; `DEVELOPER_REPOS_DIR` comes only from developer `setup_env`; `sandbox.host_paths.resolve_under_repos` scopes `--worktree`. The cache is derived at `{repos_dir}/{user_id}/.package-caches` (same mount as a venv for `link(2)`; retired the ISSUE-319 sibling masks). **Gated on `sandbox_cache_is_derived`, the repos bind's condition including `is_admin`; a boundary** (ISSUE-320): the later repos bind buries a symlink swapped in between check and `mount`. Non-admins get the fallback root or none; no separate cache write root in `native_fs_roots`. `maintenance/repos_relocate.py` moves old trees.
- **Config dir out of the sandbox.** Prompt-text files and `config.toml` live in `config/`, never bound. Exception: under `custom_system_prompt`, `config/system-prompt.md` alone (`custom_system_prompt_path`), `CLAUDE` profile only, since the CLI opens it via `--system-prompt-file`. `NATIVE` binds none; `NativeBrain` reads it in the daemon.
- **Network proxy**: `--unshare-net` + CONNECT proxy on a Unix socket, `host:port` allowlist. TLS interception only for credential-bound hosts in the task snapshot, when the broker is enabled.
- **Skill proxy.** Strips secret env vars; CLI calls go through a Unix socket injecting credentials server-side, decoupled from skill selection. Required wherever the sandbox is (`istota-skill` refuses under `ISTOTA_SANDBOXED`). DB paths (`ISTOTA_DB_PATH`, manifest `proxy_only`) go to the proxy only. Requests: `credential` (manifest lookup for git and forge helpers), `vault_list` / `vault_credential` / `vault_entry` (map from `task_env`, capped by `vault_fetch_limit_per_task`). `sandbox/credential_shim.py` goes to `{user_temp_dir}/.istota/istota-credential` (0700) on the model's PATH only, never `proxy_base_env`'s; `.istota` is re-bound read-only after the workspace (like `.developer`). The shim is a convenience, not a gate. **The socket gates which task asks** (ISSUE-550): 0600 stops other uids, not other tasks. The proxy serves only kernel-reported peers descending from pids its task registered: the brain child via `on_pid` (to `authorize_pid` first) and spawned skills (`sandbox.peer_process.reporting_pid`, revoked on exit), pinned to start time against pid cycling. Narrows rather than closes cross-task access on unsandboxed multi-user hosts; `security.proxy_peer_check` warns. Env nonce rejected (same uid reads env). A brain skipping `on_pid` gets every skill call refused.
- **Host paths in skill CLIs.** A model-chosen host path is an arbitrary read or write unless scoped. **The disposition sits on the argument** (ISSUE-447): `skills/_hostpath.host_path` stamps it; `skills/_cli.parse_and_resolve` resolves before dispatch and writes back; refusal is `reason: host_path_refused`. Modes by where bytes end up: `READ` (deferred dir, own workspace, own channel, `{mount}/Talk`, mirroring binds); `WRITE` (minus read-only roots); `EGRESS` (workspace and deferred dir, for content mailed, indexed, uploaded or persisted); `REPO`, `REMOTE`, `NOT_A_PATH` resolve nothing. Never the mount whole; symlinks rejected; no directory created at parse. `write_resolved` makes the parent at write, `O_NOFOLLOW`; `feeds export-opml` uses `_ensure_parent` since a Click CLI opens the file.
- **Coverage.** `tests/test_skill_host_paths_coverage.py` builds every parser (`build_parser`, Click `build_cli`) and requires each path-shaped argument to have a stamp or registry record (`UNSCOPED` is gone). `tests/test_skill_host_paths_refusals.py` drives each resolving stamp for refusal and acceptance. **`google_workspace` is bounded by an argv scan, a weaker claim**: `gws` cannot be walked, so `scan_argv` classifies tokens (absolute, `~`, `..`, existing relative, `=` split, short-flag tail, leading `@`) and resolves them under the read rule (`drive +upload` takes a Talk attachment). A not-yet-existing relative token passes; cwd is the workspace.
- **Nothing narrows what the daemon itself may read**; argument scoping is the only layer. Cut: a systemd read allowlist (leaves `{istota_home}` and the mount readable) and a bwrap `SandboxProfile.SKILL` (needs a conditional DB mask, `config/` bound, an ISSUE-390 carve-out, a per-skill table).
- **No Docker API in the sandbox.** No socket bound, no `DOCKER_HOST`; a `docker` binary fails at connect. The per-user `/var/run/docker.sock` proxy is retired (`docker exec` through it lost exit status, forcing the exec transport).
- **Native WebFetch** (`session/tools/web_fetch.py`): daemon netns, outside the CONNECT allowlist, credential-free (`trust_env=False`), SSRF-hardened (each resolved IP checked per hop and pinned, GET/text only, caps, untrusted delimiter). **Every user** (ISSUE-449): the `[brain.native.web_fetch]` egress policy bounds all alike; `admin_only = true` restores the gate (read by `build_allowed_tools`, not mapped onto `WebFetchPolicy`). `require_url_provenance` as non-admin default rejected: its corpus is the user half, so WebSearch-then-read fails. See `brain.md`.
- **Deferred DB**: sandboxed tasks write JSON to temp; the scheduler applies it after success. Identity (`user_id`, `conversation_token`) from the task, never the JSON. Subtasks admin-only, capped by `max_subtasks_per_task`, `max_subtask_depth`, `max_subtask_prompt_chars`.

### The credential store

`credentials/store.py` is the only live store. `names.py` owns slugging, password generation and the multi-user isolation gate. `kdbx_import.py` parses an upload and applies selected entries; `kdbx_export.py` is the sole KeePass writer and saves only to memory. Generated credentials stay in the table. `vault_retire.py` keeps one final reader and the legacy storage path resolver for one release; it imports without deletion, leaves the file unchanged, deletes the stored passphrase and old KV state, and records a retirement marker. Database startup converts leftover source values only after this marker, so startup cannot erase the ownership information the final import needs.

History is limited to `vault_entries`, ten versions per field and the configured age. Audit records names, actors and bounded metadata, never values. Web exports, recovery reveals, recipient changes, restores and purges require an emailed code tied to the native identity, action and session. The optional age backup includes credentials only, excludes connected-service secrets and wallet cards, and writes ciphertext to the user's exports folder. Keep the server secret key outside database backups.

## Shared rooms and groups in the mount plan

A turn runs with its sender's reach (ISSUE-576). `rooms.scopes.withheld_for_task(conn, task)` is the one derivation: every scope on a guest's turn, every scope on a task in a shared room no member asked there (no origin surface, as for a subtask, CLI or heartbeat task), nothing otherwise, a member's turn with a guest present included. **Nothing in an email thread room** (`rooms.scopes.is_email_thread_room`, a binding with `surface='email'` on the canonical token, asked first): the thread is the host's correspondence, so a correspondent's admitted mail runs as the host at full reach with ambient memory loaded (`ambient_memory_off` answers False ahead of the roster and audience), bounded by the untrusted-sender gate and the outbound gate rather than a scope rail (email on rooms, section 2a). `record_inbound` skips the guest branch there, so such a task has no `guest_participant_id`. The stored-author arm that used to withhold an outside correspondent's turn is gone; `_written_by_someone_else` stays only for `private_replies.my_notes_room`. A read error on that check withholds every scope. **A member's own schedule counts as their turn** (ISSUE-594): a `scheduled` task whose `scheduled_job_id` names a job row owned by the task's user, or a `briefing` task with a `briefing_name`, in a room that user is a current member of, withholds nothing (`rooms.scopes._members_own_schedule`). The job lives in the user's workspace and names the room as where its answer is read, which is the consent a live turn carries. Under bwrap a guest's turn and a restricted task cannot write that file; on an unconfined shape a guest's tools can, which `security.room_scope_confinement` names, though such a job could already be aimed at the host's private room at full reach. Membership is a `room_members` row plus, where the user has any principal participant row, a present one, because Talk records a departure only as `left_at`. A job row owned by someone else, an owner who left the room, or a scheduled task flagged `is_group_chat` still withholds every scope. A read error on the second case withholds everything. Read by `effective_disabled_skills`, the proxy's `cli_skills`, `derive_authorized_skills` and identity env (`reach_index`), setup-env hooks (env dropped), and the mount plan. A member's turn in a shared room loses only ambient memory, in prompt assembly (`.claude/rules/prompts.md`). Per-room grants, `!room share` and `[rooms] shared_room_data_policy` are gone; `room_data_grants` is dropped by migration. Rules: `transport.md` ("Multiplayer rooms"), `docs/features/shared-rooms.md`.

What a restricted task gets:

- **No workspace without `files`**: `{mount}/Users/{user_id}` and per-resource mounts unbound. Without `developer`, repos and cache go too, dropped in `resolve_sandbox_cache_dir` so bind and `UV_CACHE_DIR` agree (ISSUE-320).
- **Own temp dir**: `{temp}/{user}/emissary-task-<id>` for a guest, `room-task-<id>` otherwise, also `ISTOTA_DEFERRED_DIR`, since a guest-planted op file in the persistent per-user dir would replay at the host's authority. `executor.task_deferred_dir` reads the choice from disk (restriction can change before drain); all deferred and `email_output` readers use it. A symlink there fails the task by return.
- **No Talk bind**: the task's attachments are copied to `{control_dir}/room-attachments` (read-only, `O_EXCL | O_NOFOLLOW`), `task.attachments` names copies in memory only; `image_bind_roots` drops Talk.
- **CLAUDE profile binds no `~/.claude/projects`, `debug`, `todos`** (earlier sessions' JSONL holds `USER.md`).
- **`ISTOTA_WITHHELD_SCOPES`** is in the proxy base env only. `env_host_roots` drops the workspace without `files` and Talk when anything is withheld; `sandbox.host_paths.memory_refusal` refuses memory dirs; the `skills` guard unions it with `withheld_for_task` over `ISTOTA_TASK_ID`; nextcloud `_scoped` refuses file and share verbs without `files`, and memory paths without `memory`, after collapsing a leading `//`. Without `memory`, `files list --depth` and `files search` drop entries inside memory dirs. Residual: `share list` (`--subfiles` or no path) and `files trash list` still show them.
- **Talk writes check the live roster**: `nextcloud talk send`, `share-file`, `rename`, `describe`, `invite`, `leave`, `delete` refuse unless participants are caller plus bot; posting into the task's own room is exempt, changing a shared room never; `invite` takes only the caller; an unfetchable roster refuses. Unchecked outside a task.
- **Vault withheld whenever anything is**: `vault_credentials={}`, `vault_write_limit=0`, no prompt line. Calendar discovery skipped without `calendar`.
- **`Groups/<id>`**: each group in `rooms.scopes.task_group_ids` bound read-write as `nextcloud_group_dir` after the channel bind, sorted, de-duplicated, via `sandbox.user_scope.scoped_user_dir`. `Groups/` never bound. Empty for a guest turn, stored-mixed turn, any guest/agent/unmapped participant, no recorded readers, or readers the members do not cover; `rooms.group_id` narrows. `project_fs_roots` carries it. `ISTOTA_TASK_GROUPS` (proxy env only) gates kv/memory `--group` (`skills/_group_access`, whole-id); deferred kv re-derives from the task row.

**Without bwrap none of this confines**: Docker, macOS and standalone strip prompt, skills, allowlist and env, but tools can still read the workspace; `security.room_scope_confinement` warns. Witness: `tests/smoke/test_sandbox_shared_room.py` with a private-room control; the default suite reads argv only. The memory masks, the bot-directory self-bind and `IDENTITY_GUARD` (Stage 28) were removed with the grants: they fired only for `files` granted without `memory`, which no turn can be any more.

## sandbox/task_env.py

`build_task_runtime`: the model env, the credential split (clean / proxy-only / credential), the `SkillProxy` and `NetworkProxy`, and the read-only bind list, as a `TaskRuntime`. **Context managers are built here, entered by the caller**: they must span primary, reroute and fallback, so the `ExitStack` stays in `execute_task` around `run_with_failover`.

Load-bearing orderings: `proxy_base_env` is snapshotted before `ISTOTA_SANDBOXED` is set (skills run host-side); proxy-only split runs first, credential split on the residue (a var declared both ways stays proxy-only); `HOOK_PATH_PREPEND_KEY` is consumed after the snapshot (task-temp on host PATH is code execution); ISSUE-410 top-ups run after both splits.

**ISSUE-410 top-ups**, split by whether an uninterested CLI can be harmed. Trust stores only add a CA: `skill_cli_tls_env` puts `SKILL_CLI_TLS_VARS` (with `CURL_CA_BUNDLE`, as `sandbox.forge_cli._CARRY_EXACT`) in the shared snapshot. Proxy URLs redirect traffic (even loopback, e.g. `browse` via httpx `trust_env=True`) and can carry userinfo, so `skill_model_reachability` routes `SKILL_MODEL_REACHABILITY_VARS` (proxy triple, `ANTHROPIC_BASE_URL`) through the per-skill map and `_PROXY_LOOKUP_BLOCKED` gains them. Gap-fillers, never overrides (`credential_env` keeps `sensitive` names out); `derive_credential_set` is index-wide, so one `sensitive` `SSL_CERT_FILE` removes it for all. Open: `feeds` egress proxy. Inside `skill_proxy_enabled` only.

The network-proxy gate asks `config.security.sandbox_enabled` (asked for), the sandboxed marker `effective_sandboxing` (got); they differ on Linux without bwrap, so do not unify. `executor` is imported at function scope (cycle; keeps `monkeypatch.setattr(executor, "_bwrap_available", …)` working).

## sandbox/claude_runtime_env.py

What a task env carries only because the outer process is the `claude` CLI (`CLAUDE_CODE_OAUTH_TOKEN`), and the copy that removes it. `build_clean_env` sets it for every task; under `NativeBrain` it has no reader and one exit (Bash `echo` to whatever provider native uses, ISSUE-390). Env counterpart of ISSUE-389's Claude-only mounts.

Stripped at `NativeBrain._hello_payload` (Bash children), `NativeBrain._start_tool_server` (children read `/proc/<pid>/environ`), and `execute_task`'s `proxy_base_env` (no manifest declares it). **Scoped exception** (ISSUE-409): `executor.SKILL_MODEL_CALLERS` (`code_review`, which spawns `claude`) get it plus `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` copied into their per-skill map by `skill_model_credentials`; a copy, since it also authenticates the task's `ClaudeCodeBrain`. `_PROXY_LOOKUP_BLOCKED` gains these names.

A name list, not a `CLAUDE_*` prefix (would eat `passthrough_env_vars`), guarded over `build_clean_env`'s keys. **Copies, never mutates** `req.env` (carried across a `native -> claude_code` fallback). **`None` and `{}` differ**: `ToolEnv.subprocess_env` reads `None` as inherit-daemon-env, so the caller applies `or None` to the input. Other credentials leave via `_split_credential_env` under `skill_proxy_enabled`; proxy off with sandbox on warns (ISSUE-393). stdlib-only: `brain/native.py` cannot import `executor`.

## sandbox/tool_server.py

`python -m istota.sandbox.tool_server --fd N`, one per **task attempt**, via `build_bwrap_cmd(..., profile=NATIVE)`, placed in the cgroup from `preexec_fn`. Builds one `ToolEnv` from `hello` and binds the six core tools (`build_default_tools`) (ISSUE-389). Holds no image library (see `lib/image_sniff.py`) and must not import `istota.skills` (`tests/test_tool_server_env.py::TestTheServerDoesNotImportTheSkillsPackage`; why `sandbox/git_hardening.py`, `sandbox/forge_bin.py`, `lib/untrusted.py` live outside `skills/`).

- **Wraps nothing**: nested bwrap under `--unshare-user --disable-userns` fails, so `ToolEnv` lost the field.
- **Places nothing**: membership is inherited at fork; `cgroup.procs` is unbound.
- **Merges `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` from its own env** into `subprocess_env`, since the wrapper `exec env`s them onto this process and the frame env came from the bridge-less daemon. `NO_PROXY` is deliberately empty, so the merge tests presence; the wrapper wins collisions (the loopback bridge is the only reachable proxy).

Nothing raises past `main` (sends `fatal`); frame contents are never logged.

## sandbox/tool_server_protocol.py

stdlib-only, one `ProtocolError`. 4-byte big-endian length plus UTF-8 JSON; `MAX_FRAME_BYTES` (32 MiB) enforced on both ends. Messages: `hello` / `call` / `abort` / `shutdown` down, `ready` / `update` / `result` / `fatal` up. `ToolResult.details` does not cross (only `agent/loop.py` reads it); content blocks are plain dicts. `FrameDecoder.close()` raises on leftover bytes: a missing result is a broken server, not an unmade call.

## sandbox/cgroup.py

A cgroup v2 group per task (A6): `<unit cgroup>/task-<id>-<attempt>/` with `memory.max`, `pids.max`, `cpu.max`. A sibling of the daemon's `supervisor/` leaf (v2 forbids controllers under a process-holding cgroup). `resolve_root` takes the last `.service`/`.scope` (the first is `user@N.service`). **In the container** it first takes `ISTOTA_TASK_CGROUP_ROOT`, the private namespace's root the entrypoint's root phase remounted and delegated to uid 10001, but only when `declared_root_problem` finds it a cgroup2 directory on a mount rooted at `/` with a writable `cgroup.subtree_control`: a bind of the host's `/sys/fs/cgroup` is writable, probes clean and reads `/../..`, and is the VM's whole tree. `doctor`'s `security.task_cgroups` FAILs on a declared root with a problem or a failed `probe()`, WARNs where nothing declares one (a host unit without `Delegate=`, the web container), and SKIPs off Linux and in a task. A successful `memory.max` write is the delegation proof, so startup calls `probe()`, not `resolve_root`. Placement is `preexec_fn` since bwrap forks during setup (ISSUE-285): parent opens `cgroup.procs`, child writes `0`, `verify_placement` reads back. `place()` only for TmuxClaudeBrain. `destroy` writes `cgroup.kill` on `EBUSY` (5.14+); `read_events` names an OOM kill before `rmdir`. Fails open without `Delegate=`, said at startup. stdlib-only, never raises.

## sandbox/user_scope.py

Scoping a user id under a root (ISSUE-402). A plain join is not a check: `PurePath` drops `""` and `.` (giving every user's parent), an absolute component replaces the root, `..` is the parent on disk. **Two checks**: lexical (component became a child) and resolved (`..`, symlinks); `"."` passes resolved and only lexical sees it. **Validated resolved, returned as written**, since `sandbox.plan._bind` uses the string as the namespace destination. Returns `None`, never the shared root; callers drop the bind, root or entry. `is_scopable_user_id` is the lexical half without a root (`db.create_task` defaulted `user_id` to `""`); it refuses `.`/`..` only as whole values. Consumers: `sandbox.plan.build_mount_plan` (bind and per-resource skip), `executor.image_bind_roots`, `executor.get_user_repos_dir` (the rule since ISSUE-319), `Config.workspace_root`, the `memory` skill's `_user_id`, `db.create_task`, `sandbox.host_paths.workspace_roots` (which replaced `memory_search._indexable_roots`). `project_fs_roots` projects the same plan. stdlib-only, never raises.

## sandbox/host_paths.py

**One rule, one implementation, two derivations** (ISSUE-447). Containment: `path_under_roots` / `resolve_in_roots`. Roots: only `workspace_roots`, which scopes `{mount}/Users/{user_id}` via `sandbox.user_scope.scoped_user_dir`, guards the conversation token, and drops what it cannot scope. Skill CLIs derive from their env (`env_host_roots`, `resolve_host_path`); the daemon, with no task env, passes mount and user id explicitly (`scheduler_deferred._source_path_allowed`, `mail.drafts._confined_attachment`). **Same implementation, different roots**: deferred replay has no token or Talk; drafts are owner-workspace only (released hours later); so `talk` and `channel` are per-caller switches. Per-argument dispositions live in `skills/_hostpath.py`.

**A path a user names in their own config** (CRON.md `prompt_file`, HEARTBEAT.md `file-watch`, a briefing source's `path`) has no task env and no roots to derive, so it takes `owner_path_parts` (ISSUE-596): `/Users/<owner>/...` by exact id, no `.`/`..`/empty component, then a walk with `skills._loader.open_overlay_dir` (`O_NOFOLLOW` at every directory) and an fd-relative leaf open. The read is `storage.read_owner_text`, one copy for every caller; `file-watch` stats through the same walk. No channel and no Talk: a shared room's folder is written by everyone in it. A `prompt_file` the rule refuses drops the job rather than holding the sync, since holding kept a row with another user's text as its prompt. The fixed-name files in `{bot_dir}/config/` (TASKS.md both ways, the BRIEFINGS.md import) go through `read_user_config_file` / `write_regular_file` like the rest of that directory. HEARTBEAT.md `url-health` is admin-only, beside `shell-command`.

`scheduler_deferred`'s `import_csv` arm read `source_path` unchecked on every shape (any daemon-readable file into the health DB); it now uses `_resolved_source_path`. Replay is a boundary everywhere, so `health upload` / `import-csv` / `attach-document` are `EGRESS`, matching replay's accepted set.

**A spawner passes task identity, or every path is refused.** `whisper`'s `out_of_process` spawn lacked `ISTOTA_USER_ID` and `_pre_transcribe_attachments` logs only at debug. `--trusted-caller` and daemon-detection rejected. `executor._audio_in_reach` stages the two out-of-roots Talk shapes into the task temp dir first.

**An attachment is opened, never resolved** (ISSUE-610). `sandbox/attachment_source.py` is the one rule for audio staging, image preparation and `executor.stage_restricted_attachments`: under a root, a walk with `O_NOFOLLOW` at every component and a regular-file leaf; under none, only where the daemon writes attachments itself: `{NC_DATA_ROOT}/<user>/files/Talk/<name>` and `{temp_dir}/<name>` (`download_talk_attachments`), `{temp_dir}/whatsapp-media/<name>` and `{temp_dir}/attachments_<id>/<name>` (the WhatsApp and email upload-failure copies), and a caller's `extra` directory (audio passes the task's control dir, for `room-attachments`). A new daemon-side attachment location has to be added there, or it is refused. Residual: in-root audio is still handed to the whisper child by name, so a concurrent task can swap a component during model load; closing it means giving the child a daemon-only root. Copies are made from the open fd, and the audio landing dir (`{deferred_dir}/transcribe`, model-writable) is opened `O_NOFOLLOW` with an `O_EXCL` leaf. Under a sandbox every image becomes a copy in the control dir, because the OCR child and `NativeBrain._read_image_bytes` read the prepared path by name in the daemon. A root may match through a link *above* it (`image_bind_roots` resolves its roots), safe because the read walks from the root; the Talk anchors match by spelling only, since a link aimed at `temp_dir` would reach another user's download. Unsandboxed image preparation (`bind_roots=None`) still opens by name: the model already reads with the daemon's view there.

**Derived paths are contained by construction; writability is not** (still `write_resolved`). ## sandbox/peer_process.py

Peer identity on a Unix socket and descent from roots (ISSUE-550). `peer_pid`: `SO_PEERCRED` (translates `--unshare-pid` pids) or `LOCAL_PEERPID`. `parent_pid`: `/proc/<pid>/stat` after the last `)`, or `proc_pidinfo(PROC_PIDTBSDINFO)`. `start_time`: field 22, or `pbi_start_tvsec`/`pbi_start_tvusec`. `descends_from` takes `{pid: start}`, needs both to match, refuses on unreadable links and at pid 1. `reporting_pid` is a `preexec_fn` sending the child pid down a close-on-exec pipe, reader joined on exit; runs after `sandbox.cgroup.placement`. No roots, no access; per connection, so an admitted tunnel lasts until closed. stdlib-only, never raises.

## Credential grant snapshots

A scoped selected import grants new host-bound entries once unless tagged `istota:nogrant`. Unscoped and generated imports stay ungranted. `_credential_grants` records decisions so revocation and narrowed access survive re-import. Task-created credentials receive the creating conversation grant and extend that task's snapshot.

Reserved KV `_credential_grants`: `granted_existing` (one-time upgrade action), `revision:<name>` (kept after deletion so a recreated grant cannot revive an old snapshot; policy edits advance it), `allow_http:<name>` (explicit, default off; HTTP bindings keep `http://`), `auto:<name>` (the first-sight marker above). `_credential_fields` maps imported fields to their vault entry (from the vault parser, not suffixes). Deleting a vault credential deletes its grant and room rows in one transaction; task retention and room deletion delete task grant rows explicitly (no FK cascades).

## Credential broker CA

Grants allow every HTTP method; legacy `credential_grants.methods` is kept for compatibility, neither exposed nor enforced. Exact host and port, auth-header restrictions, the HTTP override and live revocation still apply.

`credentials/broker/ca.py`: opt-in CA under `{db_path.parent}/credential-broker` (`0700`, atomic `0600` P-256 key plus ten-year cert, cross-process lock). Corrupt or insecure records fail closed; delete `ca-key.pem` and restart to rotate. Setup rejects a location under any sandbox bind, masked or not. Leaves: exact SANs, 24 hours, bounded cache, loaded via a temp private file removed at once. HTTP/1.1 only; SNI must equal Host; upstream verified with the daemon trust context.

`build_task_runtime` writes system roots plus the CA into the read-only control dir. `TaskRuntime.sandbox_env` reaches only `sandbox_plan`'s `exec env` wrapper (never task, proxy or daemon env); the tool server passes it to Bash via `merge_proxy_env`. Node gets the CA as an extra root; others use the bundle. Broker off: nothing created. No effective sandbox: no broker trust, and setup warns.

`credentials/broker/intercept.py` intercepts only snapshot-bound hosts (others stay raw TLS); absolute-form HTTP gets the same checks for allowlisted snapshot destinations. The HTTP override never downgrades HTTPS. Per request the h11 loop checks grants, replaces placeholders only in allowed auth headers (Basic decoded first), and refuses them in URLs or the body prefix. Small responses and headers are scrubbed; large ones stream unscanned. Encoded bodies, encoded authenticated responses, trailers and upgrades are refused. Audit never holds values. Off by default; legacy fetch paths remain.

## Private skill credential channel

Each skill invocation gets a socketpair via `ISTOTA_CRED_FD` / `pass_fds`, never the model; the skills package marks it close-on-exec before loading skill code. `_credref` resolves at parse time over a per-name duplicate. The proxy accepts only credential reads there, sets provenance itself, and charges the attempt budget. With the broker on it checks the grant (room scope, `allow_scheduled`, revision), refusing `credential_not_granted` or `credential_changed`; a grant read error refuses. Names created this attempt by `vault_create` are exempt (`_created_names`, in memory) for create-then-fill, since the snapshot was frozen before the create's conversation grant; later tasks use that grant. Public reads follow the reveal policy, not grants. Values come from the live lookup.

Both ends are closed and the reader joined on success, timeout or spawn failure. An invalid fd refuses without falling back; callers with no fd use the public socket, under the reveal policy.

## Public credential reveal enforcement

`SkillProxy._serve_vault_credential` (and `_serve_vault_entry`, per member, refusing the entry if any member is unrevealable) charges the budget and checks presence before reading live `credential_bindings.revealable`; under enforcement permission and value are read in one transaction. Only the private dispatcher sets `trusted_skill=True`; public `mode` or trust claims carry no authority. Unmarked public reads log `credential_reveal action=would_refuse reason=credential_brokered` at WARNING, or return `credential_brokered` with `[security.credential_broker] enforce_reveal = true`. Predicate `CredentialBrokerConfig.reveal_enforced` also needs `enabled` (no placeholders otherwise, so every git and forge read would fail; `load_config` warns). Missing metadata means no reveal; names via `label_for_display`, values never logged.

Covers `get`, both `run` forms, raw socket clients, and the public manifest `credential` branch (manifest vars and forge tokens have no reveal marker). Host-side injection and the private fd are unaffected; `list`, `placeholder`, `new` unchanged. Enable after a week with no would-refuse events; nothing enables it automatically. Devbox credentials are outside this policy.


Browser secret capture uses `read_secret` (with `read_recovery` as a compatibility alias), the element's own HTTPS frame origin and the private credential channel. `vault_secret_capture` and the stdin setters share `_store_captured_secret`: write budget, isolation, snapshot/grant reach, shape validation, then an audited generated-credential write. Captured values enter browser redactions before a store refusal can return. Recovery formats and spent indices live in `recovery_code_state`; export prefixes spent lines with `(used) `. The dependency-free `lib/secret_shapes.py` receives the existing TOTP parser from its caller, because `lib/` leaves cannot import each other.
